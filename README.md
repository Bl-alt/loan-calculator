# Калькулятор кредита и вклада

Считает кредит или вклад и сразу показывает всю картину: ежемесячный платёж, полный график, переплату, сравнение аннуитетной и дифференцированной схем и эффект досрочного погашения. Все расчёты точны до копейки.

Чтобы запустить введите в терминал:
npm install
npm run dev

## Возможности

- **Кредит:** сумма, ставка, срок (в месяцах или годах), дата выдачи, аннуитетный или дифференцированный платёж.
- **Два режима начисления процентов:** упрощённый «по месяцам» (остаток × ставка / 12) и точный «по дням» (остаток × ставка × дни / 365 или 366).
- **График платежей:** дата, платёж, проценты, основной долг, досрочный взнос, остаток; итоговая строка.
- **Сравнение схем** на одном экране: таблица и график платежей по месяцам.
- **Досрочные погашения:** разовые и ежемесячные, с выбором «уменьшить срок» или «уменьшить платёж»; показывает сэкономленные проценты и на сколько сократился срок.
- **Вклад:** с ежемесячной капитализацией или без, с ежемесячными пополнениями.
- Валидация ввода, тёмная тема (системная или выбранная вручную), вёрстка от 375 px.

## Стек

React 18 + TypeScript (strict) + Vite, [decimal.js](https://mikemcl.github.io/decimal.js/) для денег, [Plasma](https://plasma.sberdevices.ru/web/) (открытая дизайн-система Сбера: `@salutejs/plasma-web`, тема `plasma_homeds`, шрифты SB Sans) для интерфейса, Recharts для графиков, Vitest + Testing Library для тестов, ESLint + Prettier.

## Формулы

**Аннуитетный платёж**

```
P = S × i / (1 − (1 + i)^(−n)),   i = годовая ставка / 12 / 100
```

Каждый месяц: проценты = остаток × i, в счёт долга идёт P − проценты.

**Дифференцированный платёж:** тело долга гасится равными частями S / n, проценты начисляются на остаток:

```
платёж = S / n + остаток × i
```

**Проценты по дням:**

```
проценты = остаток × ставка × дни / дней_в_году
```

Если период переходит через Новый год (например, 15.12.2023 → 15.01.2024), он делится на две части, и каждая считается со своим знаменателем: 16 дней / 365 и 15 дней / 366.

**Вклад с ежемесячной капитализацией:** каждый месяц проценты = остаток × r / 12 добавляются к телу; без пополнений это даёт `S × (1 + r/12)^m`. Без капитализации проценты начисляются только на внесённые деньги и выплачиваются отдельно.

**Досрочное погашение:** взнос вносится в дату очередного платежа сверх него и уменьшает остаток.

- «Уменьшить платёж»: аннуитет пересчитывается на оставшийся срок (для дифференцированного: остаток / оставшиеся месяцы).
- «Уменьшить срок»: платёж остаётся прежним, новый срок ищется как `n = −ln(1 − B·i / P) / ln(1 + i)`.

## Технические решения

### Почему decimal, а не number

`0.1 + 0.2 !== 0.3`, а `2.675` в double хранится как `2.67499999…` и округляется не туда. На 240 платежах такие ошибки накапливаются в копейки и рубли. Все суммы в ядре имеют тип `Decimal` (decimal.js, 40 значащих цифр, отдельный клон конструктора, глобальная конфигурация не меняется). `number` появляется только в UI для форматирования и точек графика, когда значение уже округлено до копеек.

### Округление и корректировка последнего платежа

- Каждая сумма в строке графика (платёж, проценты, тело) округляется до копейки по правилу half-up.
- Аннуитет считается с полной точностью и только потом округляется.
- Из-за округления после n-го платежа остался бы «хвост» в несколько копеек. Поэтому последний платёж, как у банков, забирает весь остаток: `тело = остаток`, `платёж = остаток + проценты`. Остаток в конце всегда ровно 0,00, это проверяется тестом на сетке из 600 комбинаций параметров.

### Граничные случаи

- **Ставка 0:** формула аннуитета делит на ноль, поэтому это отдельная ветка: P = S / n.
- **Досрочный взнос больше остатка:** обрезается до остатка, кредит закрывается.
- **Взнос в последний месяц:** гасить уже нечего, взнос игнорируется.
- **31-е число:** дата платежа отсчитывается от исходного дня с прижатием к концу месяца: 31.01 → 28.02 → 31.03 (а не 28.03).
- **Режим по дням + высокая ставка:** проценты за 31-дневный месяц могут превысить аннуитет. Тогда платится только процент, долг не растёт.
- **Ввод:** сумма 1 ₽…1 млрд ₽, не больше двух знаков после запятой, ставка 0–100 %, срок 1–600 мес.

### Интерфейс на Plasma

- Компоненты берутся из CSS-сборки `@salutejs/plasma-web/css`: TextField, Segment, Radiobox, Tabs, Button, IconButton, Note, типографика. styled-components не нужен.
- Цвета, шрифты и типографика задаются токенами темы `plasma_homeds`. Светлая и тёмная версии переключаются классом на `<html>`; класс ставится до первого рендера, чтобы при тёмной теме страница не мигала светлой.
- Обёртки в `src/ui/common` (`Field`, `Segmented`, `RadioChoice`, `Stat`) отделяют экраны от библиотеки: при смене дизайн-системы правится только эта папка.
- Цвета графиков взяты из токенов темы (акцентный зелёный и синий info) и проверены на различимость при дальтонизме и контраст 3:1 в обеих темах.
- Что пришлось дописать поверх Plasma:
  - `as` у заголовочных компонентов в CSS-сборке не работает, поэтому семантические `h1`/`h2` оформлены CSS-классами на тех же типографических токенах;
  - состояние выбора для скринридеров (`aria-pressed` у сегментов, `aria-selected` у вкладок);
  - `SegmentGroup` в CSS-сборке пробрасывает prop `filledBackground` в DOM. Это даёт предупреждение React только в dev-режиме, на работу не влияет.

### Тесты

- Юнит-тесты на каждую формулу и модуль; покрытие `src/core` 100 % строк (порог в `vite.config.ts`).
- Эталонные значения получены **независимой реализацией** на Python `Decimal` (`scripts/crosscheck.py`), а не из того же кода, который проверяется.
- Инварианты на сетке «сумма × ставка × срок × тип × режим»: остаток = 0,00, сумма тела = сумме кредита, срок ≤ n.
- Smoke-тесты интерфейса на Testing Library (заглушки `matchMedia`, `scrollTo`, `ResizeObserver` для jsdom лежат в `src/ui/test-setup.ts`).
- `src/core/bankReference.test.ts` — таблица для сверки с калькуляторами банков (пока пустая, см. «Что дальше»).
